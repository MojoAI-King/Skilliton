# Maintain: this repository's own steps

Kind: Living. Run these as part of `/maintain` (or `/workflow:maintain`) in this repository, in addition to the generic ritual. Every gate runs as its own step with its exit status read on its own line; never pipe a gate into `head`, `tail`, or `grep` before a commit (docs/LESSONS.md).

1. **Look for other sessions first.** `git worktree list` and `git for-each-ref refs/heads`. Another agent may be working here (agent lanes live under `.claude/worktrees/`; other sessions have used sibling folders). Preserve unassigned work and never stage or publish another lane's changes casually. The integrating session merges a finished lane only after checking its base, its write set and its report, then runs the full suite on the combined tree (step 2); a lane's own green does not count.
2. **Run the offline checks, one step each:**
   - packaging: `node scripts/packs.test.mjs`, `node scripts/packs.test.mjs --self-test`, and `claude plugin validate --strict` for `.` and each `packs/*/plugins/*/` (use a Claude Code build that has `--strict`); guides: `node scripts/docs.test.mjs` and `node scripts/docs.test.mjs --self-test`
   - runtime: `node scripts/skilliton.test.mjs`, `node --test scripts/stack.test.mjs scripts/dispatch.test.mjs scripts/prepare.test.mjs scripts/migrate.test.mjs scripts/records.test.mjs`, `node scripts/lifecycle.test.mjs`, `node --test scripts/handoff-write.test.mjs`, `node --test scripts/security-evidence.test.mjs scripts/collectors.test.mjs`, `node scripts/release.test.mjs`, `node --test scripts/join.test.mjs`, `node --test scripts/preflight.test.mjs`, `node --test scripts/git-config.test.mjs`, `node --test scripts/rename.test.mjs`, `node scripts/delivery.test.mjs`
   - hooks and tools: `bash scripts/guardrails.test.sh`, `bash scripts/handoff-hook.test.sh`, `bash scripts/hook-fixture.test.sh`, `bash scripts/statusline.test.sh`, `bash scripts/drift-check.test.sh`, `node scripts/setup.test.mjs`, `node scripts/token-cost.test.mjs --reference` (the reference part reports NOT RUN on a machine without the 2026-09-14 to 15 transcripts), `node --test scripts/read-guard.test.mjs`, `node --test scripts/gate.test.mjs`, `node scripts/evidence.test.mjs`
   - end to end: `node scripts/autopilot-demo.mjs`, `node scripts/rehearsals/projects.mjs --no-evidence`, `node scripts/demo-day.mjs` (the five demonstration steps; add `--claude <path>` to drive the real client)
   - rehearsal judgement: `node scripts/rehearsals/enrollment.mjs --self-test` (needs no Docker)
   - names: `node scripts/names.test.mjs` and `node scripts/names.test.mjs --self-test` (no current file uses the product's earlier name; docs/BRANDING.md)
   - lint: `node scripts/lint.test.mjs` and `node scripts/lint.test.mjs --self-test` (the 600 line ceiling on plugin runtime files with its ratchet of pinned files, unused imports, `console.log` in a runtime, a command module that does not export `help` and `run`, and a `package.json` outside the fixtures; decision 2026-09-20-a-dependency-free-in-repo-lint-and-a-siz-da3d)
   - dead code: `node scripts/deadcode.mjs` and `node scripts/deadcode.mjs --self-test` (an export in the plugin runtimes that nothing imports, and a block of seven meaningful lines that repeats; both allow lists take a row only with a docs/BACKLOG.md id and a reason, and the coverage line names every dynamic import and every module it could not follow)
  - report card: `node scripts/report-card.test.mjs`, `node scripts/report-card.mjs --check` and `node scripts/report-card.mjs --self-test` (the bars in docs/REPORT_CARD.md match the batch files under docs/areas/; run `--apply` after ticking an item)
   - endpoint security: `node scripts/allowlist.test.mjs` and `node scripts/allowlist.test.mjs --self-test` (docs/IT-ALLOWLIST.md names every program the code starts and every place it writes outside a repository; the writes check runs a scenario in an empty home folder and needs git and ssh-keygen)
   - small footprint: `node scripts/footprint.test.mjs` and `node scripts/footprint.test.mjs --self-test` (no network code, no administrator rights, nothing left running, no system paths, every shipped file a text script)
   - public safety: `bash scripts/scrub-check.sh`, `bash scripts/scrub-check.sh --self-test`
   - records: `node scripts/backlog.test.mjs` and `node scripts/backlog.test.mjs --self-test` (docs/BACKLOG.md and docs/BACKLOG_ARCHIVE.md agree: no item in both, no finished row in the live queue, every archived row dated), `node scripts/living-docs.mjs --check` and `node scripts/living-docs.mjs --self-test` (the RESUME HERE block within 24 lines and 4500 bytes, five Earlier entries at most, the milestone table in docs/STATUS.md current against PLAN.md section 7, the current-state paragraph within 1000 bytes with its archive present; run `node scripts/living-docs.mjs --apply` after editing PLAN.md section 7)
3. **Plugins changed?** Bump that plugin's `version` in its `.claude-plugin/plugin.json` (installed copies update only when it changes). A harness template change also reaches prepared projects as migration `0100-instructions-<hash>`; say so in the release notes.
4. **Eval run?** Use the recorded command so runs compare: `claude plugin eval packs/base/plugins/workflow --trust-plugin --no-publish --scaffold -j 4 --output-dir <folder outside the repository> --keep-temp --judge-model sonnet --max-cost-usd <ceiling> --allow-tools Bash Write Edit` (add `--case <name>` to run one case; the tool grant comes last because it takes a list). Since 2026-09-16 the judge is sonnet, because the default judge failed replies that met their rubric (DECISIONS.md O12); scores judged before and after that change are not directly comparable. Never commit the raw result. `node scripts/evidence.mjs <aggregate-result.json> --sha <commit> --notes <notes.md>`, with every failed check diagnosed from its kept transcript in the notes, and the exact command written in the notes.
5. **Paid and live checks, when the change touches client behavior:** `bash scripts/live-capability-probe.sh`, `node scripts/rehearsals/live-clients.mjs --claude <path> [--codex <path> --codex-home <logged-in isolated home>]`, `node scripts/rehearsals/company-release.mjs --claude <path> --codex <path> [--with-eval]`, `node scripts/rehearsals/fork.mjs --claude <path> --codex <path>` `node scripts/rehearsals/machine.mjs --claude <path> --codex <path>` (free: installs need no login; the machine rehearsal also reads this public repository from GitHub), and `node scripts/rehearsals/enrollment.mjs [--claude-version <x.y.z>]` (free, needs Docker: Claude Code managed settings in clean Linux containers, asserting the behavior measured on 2.1.274), and the free `bash scripts/codex-offline-probe.sh`. Each writes its summary under `evidence/` only after the scrub check passes on it.
6. **Docs, reconciled rather than rewritten:** `docs/HANDOFF.md` is written by the day's checkpoints (`skilliton checkpoint --handoff ... --apply` on main rotates the previous block to Earlier and archives beyond five); here compare its Written time with `git log --since` and write one more checkpoint only when the block is behind. `skilliton index` without `--apply` must report every index current. When the current-state paragraph of docs/STATUS.md is rewritten, the superseded paragraph moves unchanged to the top of docs/STATUS_ARCHIVE.md under `### <date>`, and the milestone table below it is regenerated with `node scripts/living-docs.mjs --apply`. Then the judgment records: new decisions and lessons as entry files (`skilliton record decision "<title>" --apply` and `skilliton record lesson "<title>" --apply`, filled in, then `skilliton index --apply`; never appended to DECISIONS.md or docs/LESSONS.md, whose older entries are adopted history), the open-items table in `DECISIONS.md`, docs/COVERAGE.md when something is exercised for the first time, `docs/CONTRACTS.md` when a shared name or format changed, `PLAN.md` sections 6 and 7, README.md, docs/HOW-IT-WORKS.md (its diagrams and its proven-or-not table) and docs/ONE-PAGER.md, docs/CLIENTS.md when a client behavior was measured, docs/ONBOARDING.md and docs/RELEASING.md when a command changed, docs/AUTOPILOT_START_HERE.md and docs/AUTOPILOT_INTEGRATION.md for the build index and open seams, releases/SCHEMA.md when release contracts change, and a BEHIND label on any Living doc that is out of date. When a milestone's evidence lands, also reread every status claim it could have changed: `grep -rn -i "not built\|design, not built\|still required\|not verified\|unverified\|not rehearsed" README.md PLAN.md docs releases --include='*.md'` and reconcile each hit with the evidence (docs/LESSONS.md).
7. **Before pushing:** `bash scripts/scrub-check.sh --history` on the branch you are pushing, as its own step (it needs `~/.config/skilliton/denylist` and scans the commits that branch reaches; `--history-all` scans every local ref, including other sessions' unpushed branches, and is what CI runs), then push `main` only, then read the CI run's step results, not just its colour.
8. **Keep one direction:** PLAN.md v4 is the product authority. Distinguish implemented, verified and target behavior. A plugin update does not by itself update project Markdown or configuration. Do not copy older branch plans over the current roadmap.
