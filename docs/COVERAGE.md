## Delivery gate

Since 2026-09-20 the gate also audits the files each push changes and rejects a finding by name, with a signed policy able to turn it off.
- Exercised 2026-09-21: the GitHub adapter on a throwaway hosted repository with a ruleset (pull request and the `skilliton-delivery` check required): a direct push refused, the check failing on a defective change, the pull request BLOCKED (`evidence/live/2026-09-21-hosted-delivery-gate.md`). Not run: a clean change merging, the merge queue, the policy-path branch.

## The self-running audit

- Exercised: the six rules over planted flaws and clean look-alikes, each asserted at its exact line, with the matched text never printed (`scripts/audit.test.mjs`, and `--self-test` proving each check can fail); the merge gate rejecting a push whose changed files carry a finding and accepting the same line once it carries an allow marker (`scripts/delivery.test.mjs`); the Stop routine's sentence (`scripts/lifecycle.test.mjs`, with a mutation check that drops it); the pre-push hook installed in a fixture repository, with its refusals for a foreign hook and for `core.hooksPath`. Run against this repository on 2026-09-21, before B45: **0 findings over the 47 files wave 7 changed**, with 6 allowed lines carrying a reason, and **41 findings over all 475 files it has ever changed**, every one of them a rule's own pattern or a planted fixture. That difference is the point of auditing a change rather than a tree. After B45 (commit a9eea9e): **0 findings over all 480 files, with 45 allowed lines carrying a reason**, so the whole tree is now as clean as a scoped run and every exempted line says in its own words why. Re-run at the end of wave 8 (commit 18b8fd0): **0 findings over all 544 files, with the same 45 allowed lines**, so the wave's new runtime, tests and docs added no finding and needed no new exemption. Thirty-nine of those lines carry a trailing marker; the two that could not, both JSON descriptions, were reworded off the literal flag instead.
- Exercised outside this repository (2026-09-22): two public open-source repositories audited whole from an empty base commit. A child-process library had 17 findings in 638 readable files (6 not read as text), all `shell-true` in tests of its own shell option, and none in its source. A web framework had 0 findings in 214 files (DECISIONS.md O28).
- Not exercised: a prepared customer repository; known scanners run only when installed, which is not built; the `security-audit` skill; the eval half of M10, which asks whether a skill helps a model act on a finding, and which B20 handed to B17 (B17 closed on 2026-09-21 having evaluated four cleanup skills, none of whose cases put a model in front of an audit finding, so the question is still unasked and is now docs/BACKLOG.md B48); files in any language but the JavaScript, shell, JSON and Markdown this repository holds; a recorded observation going stale in a real project rather than a fixture.

Not exercised: the note in the interactive VS Code extension.
- Exercised for real (2026-09-21): one dispatch of two lanes on this repository. `dispatch --apply` made each lane's worktree, brief and task record, both lanes finished real backlog items and were merged the same evening, and each lane's peak context, read by the meter's definition, stayed under its ceiling (evidence/live/2026-09-21-dispatch.md).
