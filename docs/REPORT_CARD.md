# Report card: what Skilliton is graded against, and how far each area has come

Kind: Living. Updated whenever a batch under docs/areas/ ticks an item; regraded when the owner asks.

## What this grades against

On 2026-09-18 the owner asked for an honest grading of this repository against their intent, not against the roadmap's own milestones. The intent, in ten areas:

1. **The autopilot loop.** In a prepared repository the assistant starts from the handoff, records the task, checkpoints as it works, reviews before committing and hands off, with hooks enforcing what can be enforced.
2. **Auto-harness on arrival.** Once Skilliton has run in a terminal on a machine, any repository opened there is harnessed with one yes.
3. **Any environment.** Terminals, VS Code, other IDEs and other AI coding tools, each with a measured column.
4. **Token efficiency that improves the work.** Bounded context, the read guard and the gate in real use, and the meter showing the direction of travel.
5. **Repository maintenance and health.** Short living documents, generated where they can be, with tests holding the relationships.
6. **Clean code and an organized repository.** Lint, size ceilings, dead code found, a cleanup pack with evidence.
7. **Dispatch into worktrees.** Notes become lanes, lanes become worktrees with bounded agents, records merge back.
8. **Make it yours.** A fork releases a signed version and installs pinned to it, including from a private repository.
9. **Security and shared delivery.** The hosted gate rehearsed for real; the audit running itself.
10. **Proof it helps people.** A real new builder and a measured comparison. Deferred by the owner to their own use; nothing here is scheduled.

**The ship bar is A- in every area but the tenth.** An area is at A- when every one of its batch bars is at 100 with evidence linked, and no open owner input blocks it. Where an owner input is open (a Windows machine, a signing key, a throwaway repository), the area's file says so and the bar stays where it is; a bar is never ticked on belief.

## How the bars are computed

Each area folder under `docs/areas/` holds one `AREA.md` and its batch files. A batch has an `## Acceptance` list of checkbox items. The bar is the count of ticked items over all items, and nothing else: it is not a time, a cost, or a savings figure, and the letter grade is a separate judgment recorded in the history table below. A ticked item must end with `(evidence: ...)` naming what proves it, or the check refuses.

```
node scripts/report-card.mjs            print the bars
node scripts/report-card.mjs --apply    rewrite the block above and each AREA.md's Build progress line
node scripts/report-card.mjs --check    fail when the written bars are stale (runs in CI and in docs/MAINTAIN.md step 2)
node scripts/report-card.mjs --self-test  prove each of its checks can fail
```

The bars and the grades can disagree, and on 2026-09-18 they do: a grade of B with a bar near 0 means the area works today (the grade) but the batches that take it to A- have barely started (the bar). The bar tracks the road; the grade is the judgment at each milestone of it.
